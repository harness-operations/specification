# Harness Operations Reference Model 0.3

Reference Model 0.3 is the first **Applied Harness Operations** release.

The core reference model remains intentionally small and descriptive. v0.3 focuses on applying it to real Harness interfaces, operational failure modes, and evidence-backed comparison.

## Added

- A canonical comparison methodology and machine-readable landscape dataset with explicit capability, mechanism, evidence, freshness, unknown, and not-applicable semantics.
- Fifteen operational capability definitions used consistently across role-separated landscape rows.
- Version-scoped Harness mappings for:
  - OpenAI Codex App Server 0.157.0.
  - Anthropic Claude Code CLI 2.1.282.
- Broader role-separated research rows for Cursor CLI, OpenCode 1.18.32, Agent Executor 0.3.0, TypeSafe Jev API 0.2.0, and Paseo 0.9.2.
- Directed Paseo integration observations, explicitly marked partial where Harness Operations has not independently live-tested the product pair.
- The executable approved-artifact handoff fixture with failure tests for mutation-after-review, malformed/missing decisions, denial/expiry, revocation, uncertain outcomes, reconciliation/retry, and workspace escape.
- Three operational patterns:
  - Approval valid at execution time.
  - Stop, revoke, and recover.
  - Model-informed decisions, code-enforced consequences.
- Exact-version, credential-free live interface smoke evidence for Codex and Claude Code machine-control surfaces.
- An external-review/reproduction template and an explicit record that v0.3 has not yet received qualifying independent reproduction evidence.

## Strengthened

- Comparison CI now requires complete capability rows and separates documentary evidence from executed tests.
- Product/runtime/decision-service/control-layer roles remain distinct; no weighted score, product ranking, certification, or “best” label is introduced.
- The Standards Landscape retains the rule that implementation prior art belongs only when it materially clarifies an operational boundary.
- Current external version/maturity claims were rechecked during the final adversarial review.

## Important limitations

- Credentialed live behavior for Codex and Claude Code—such as real approval execution, sandbox side effects, authenticated resume/interruption, and provider telemetry—remains documentation-backed unless separately marked live-tested.
- Paseo adapter records show implementation evidence, not independent end-to-end compatibility proof.
- No independent external reproduction satisfying the project methodology was received before the v0.3 release candidate. v0.3 therefore makes no claim of community validation or endorsement.
- The comparison dataset is editorial/build infrastructure, not a Harness Operations wire protocol, compatibility certification format, or conformance schema.

## Unchanged posture

Reference Model 0.3 still does **not** define a new wire protocol, common Harness lifecycle, centralized control-plane requirement, registry, or certification program.

New common interoperability surfaces remain future work only where implementation evidence demonstrates a cross-Harness gap that existing standards do not already solve.
