# External review and reproduction

Harness Operations welcomes independent attempts to apply the reference model and Applied Harness Operations patterns to real operational systems.

The purpose is not endorsement. Useful review identifies where the model is ambiguous, unnecessary, incomplete, or contradicted by implementation experience.

Use [TEMPLATE.md](TEMPLATE.md) for a review or reproduction report.

## Evidence principles

- Identify the exact system/interface/version/configuration.
- Describe the concrete operational failure, handoff, or control being evaluated.
- Separate documented behavior from behavior actually observed.
- Preserve unknowns and uncertain outcomes.
- Redact credentials, personal data, proprietary source, private prompts, and sensitive traces.
- Do not claim compatibility or security properties beyond the tested scope.
- Maintainer/vendor submissions follow the same evidence rules as independent submissions.

Reports can be proposed through a GitHub Issue or Pull Request. Material defects in the reference model should become focused issues rather than being hidden in a review report.
