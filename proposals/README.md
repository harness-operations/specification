# Proposals

Most Harness Operations changes should begin as GitHub Issues and be implemented through focused Pull Requests.

The `proposals/` directory is reserved for changes that are too substantial to review effectively in an ordinary Issue/PR flow—for example, a proposed interoperability surface, a major reference-model extension, or a change that requires a persistent design record across several documents.

Reference Model 0.1 intentionally does not define a formal RFC lifecycle, voting process, working groups, or proposal numbering requirements. If the project develops enough contributors and proposals to need a stronger process, that process should be designed in response to demonstrated need.
